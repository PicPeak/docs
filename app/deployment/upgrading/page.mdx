# Upgrading

## The routine upgrade

```bash
docker compose -f docker-compose.production.yml pull
docker compose -f docker-compose.production.yml up -d
```

Database migrations run automatically on start, and the backend refuses to serve
against a half-migrated database rather than starting in a broken state. On the
[all-in-one image](/deployment/single-container) the same applies — re-run your
`docker run` command with the new image.

<Callout type="warning">
**Back up first, every time.** See [Backup & Restore](/guides/backup-restore).
Some migrations repair data rather than only adding columns, and those cannot be
undone by pulling the old image back — the schema change is reversible, the data
correction is not.
</Callout>

Which image tag you land on depends on `PICPEAK_CHANNEL` — see
[Release Channels](/deployment/release-channels).

## Release-specific notes

Only releases that need something from you are listed here. If a version is not
mentioned, the routine upgrade above is all it needs.

### v3.46.x → v3.132.1

This release promotes roughly two months of beta work onto the stable channel at
once, so it carries more change than a normal stable patch.

<Callout type="error">
**One-way.** Migration `186` deletes duplicate external-photo rows and `187`
rewrites stored external paths with no record of the previous base — both
irreversible by design. Once an instance is on v3.132.1 it cannot be moved back
to a v3.46.x image. Take a backup you have actually tested restoring.
</Callout>

Two visible side effects on first boot, both verified against a real v3.46.13
database:

- **Every lightbox preview regenerates.** Migration `188` clears all stored
  preview keys, so each photo re-renders its preview the first time it is
  viewed. Nothing is lost, but on a large library expect a noticeable CPU spike
  — and S3 egress, if your originals live there — spread over the first hours of
  use rather than a one-off cost during the upgrade itself.
- **A fixed pixel height on gallery tiles is rewritten.** Migration `181`
  replaces any `.photo-card img { height: <N>px }` with `height: 100%`,
  including a rule you wrote yourself in
  [Custom CSS](/guides/custom-css). All seven layouts size the card and expect
  the image to fill it, so a pixel height there detached the image from its
  tile. If you set one deliberately, your tiles will change.

Nothing is switched on for you. Face recognition, PicTransfer, newsletters, CRM,
accounting, contracts, quotes and projects all stay off by default, existing
permission grants are projected forward so no account loses capability, and the
optional `picpeak-ml` sidecar is not started unless you ask for it
(`docker compose --profile faces up -d`).

One thing you will be asked: [anonymous usage
reporting](/features/usage-reporting) is off by default, but an existing install
gets a single opt-in prompt on the first admin login after the update. Declining
is a permanent answer.

<Callout type="info">
**Why the version jumped from 3.46.13 to 3.132.1.** Stable and beta count
releases independently — beta bumps on every merge, stable only on a promotion —
so the numbers drift far apart for identical code. A promotion now pins stable to
beta's current base version. The jump is the two channels meeting, not 85
releases of change — stable v3.132.1 carries the same work as beta v3.132.1-beta.0.
</Callout>

### Permission, session and backup hardening

Builds containing [PicPeak PR #1477](https://github.com/PicPeak/picpeak/pull/1477), [PicPeak PR #1478](https://github.com/PicPeak/picpeak/pull/1478), [PicPeak PR #1483](https://github.com/PicPeak/picpeak/pull/1483), [PicPeak PR #1485](https://github.com/PicPeak/picpeak/pull/1485), [PicPeak PR #1486](https://github.com/PicPeak/picpeak/pull/1486), [PicPeak PR #1489](https://github.com/PicPeak/picpeak/pull/1489), [PicPeak PR #1491](https://github.com/PicPeak/picpeak/pull/1491), [PicPeak PR #1493](https://github.com/PicPeak/picpeak/pull/1493), [PicPeak PR #1495](https://github.com/PicPeak/picpeak/pull/1495) and [PicPeak PR #1497](https://github.com/PicPeak/picpeak/pull/1497) upgrade with the routine steps. Migration `217` only adds two columns, and the Docker Compose secrets volumes are created and filled on the next `docker compose up`. A few behaviours change:

<Callout type="info">
**Check your logo folders.** Only image files are served from `storage/uploads/logos` and `storage/uploads/favicons` now. Older versions could leave other files there; look for any and delete them.
</Callout>

- **Mail servers.** Changing an SMTP, IMAP or mail-account server's host, port, username or TLS setting requires entering its password again. Sent invitation and password-reset emails cannot be resent from Messages. See [Email Notifications](/features/email-notifications#mail-server-passwords).
- **SSO.** Changing the issuer URL or client ID requires entering the client secret again, and role mappings can only target roles within the editor's own permissions. See [Admin SSO](/features/admin-sso#role-mapping).
- **Backups.** The backup destination, database inclusion, restores and `.picpeak` imports are Super Admin only. See [Backup and Restore](/guides/backup-restore).
- **Events and roles.** Roles other than Super Admin and Admin see only their own and ownerless events; Admin sees every event but not other owners' share links; thumbnail settings need `settings.edit`. See [Roles & Permissions](/features/multi-admin#events-you-do-not-own).
- **Galleries.** Changing a gallery password, client PIN or client link signs out the sessions opened with the old one, guest uploads respect the photo cap, and the admin preview follows the session timeout. See [Creating Events](/guides/creating-events#access-control).
- **Feedback.** The per-event feedback rate-limit switch is gone; the instance-wide limits apply. See [Feedback](/features/feedback#settings).
- **3.46.x** is end of life. See [Release Channels](/deployment/release-channels#security-support).

## If an upgrade goes wrong

- **The backend will not start.** Check its logs first
  (`docker compose logs backend`); a failed migration names itself and leaves the
  database untouched rather than half-applied.
- **Galleries load but images are missing.** Usually the
  [API rate limiter](/guides/admin-settings/security#api-rate-limiting) rather
  than the upgrade — a `429` is a completed request, so the browser console shows
  nothing.
- **You need to go back.** Restore the backup. Pulling the previous image is not
  enough on a release whose notes above say it is one-way.
