# Admin Settings

The **Settings** page (left rail in the admin panel) groups every system-wide knob in PicPeak. Settings live in the `app_settings` table as key/value pairs and most apply immediately on save — no restart needed.

The settings are grouped into eight groups. A group only lists the tabs your role may open, and tabs for a feature that is switched off on the **Features** tab are hidden:

| Group | Tabs |
|---|---|
| **General** | Features, General, Event Creation, Event Types |
| **People & access** | Users (only while user management is on) |
| **Content & Appearance** | Branding, Categories, Thumbnails, Download resolutions, Custom CSS, CMS Pages, Slideshow |
| **Communication** | Email Settings, Moderation, PicTransfer |
| **Privacy & Security** | Security, Single Sign-On, Image Protection, SEO & Robots |
| **Integrations** | API Tokens, Webhooks |
| **CRM-Settings** | Business profile, CRM behaviour, Contracts, Accounting, WhatsApp |
| **System** | Status, Health, Analytics, Product usage & feedback, Backup |

**Status** shows what the instance is running right now (services, queues, storage, version); **Health** lists background failures that need attention, such as stuck emails and failed checks.

## Finding a setting

While you are on Settings, the admin sidebar shows the settings groups in place of the main menu. The **Search settings…** field at the top of it filters the tabs as you type. It matches tab names and also what a tab does, so "SMTP" finds Email Settings.

To search the whole admin area, press **Ctrl K** (**⌘K** on a Mac) or click the search button in the header. The palette lists pages and settings tabs together.

## Saving

Each tab has one save bar at the bottom of the window. **Save changes** and **Discard** stay disabled until you change something; then the bar shows **You have unsaved changes**. Leaving the page or closing the browser tab with unsaved changes asks first (**Discard and leave** or **Stay**). Switches that save the moment you flip them are not part of the bar.

## Moved pages

Several pages that used to be top-level entries in the admin sidebar now live elsewhere. The old addresses redirect, so bookmarks and links in emails already sent keep working:

| Old address | Now |
|---|---|
| `/admin/archives` | `/admin/events/archives` (Galleries → Archives) |
| `/admin/users` | `/admin/settings?tab=users` |
| `/admin/system-health` | `/admin/settings?tab=health` |
| `/admin/workflows` | `/admin/automation/workflows` |
| `/admin/email`, `/admin/branding`, `/admin/event-types`, `/admin/backup`, `/admin/cms` | the matching tab under `/admin/settings?tab=…` |

## Where settings are stored

Every setting in this section persists to the `app_settings` table:

```sql
SELECT setting_key, setting_value FROM app_settings WHERE setting_key = 'general_default_expiration_days';
```

Most settings are cached in-process for performance; the relevant cache is invalidated automatically when you save in the UI. Editing the row directly in the database is supported but requires a backend restart to pick up.
